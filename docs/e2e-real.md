# 실제 모드 화면 e2e (v8)

실행 2026-10-08 03:00~03:13 · 브랜치 `e2e-real` · 화면을 로컬 백엔드에 붙여(가짜 데이터 없이) 핵심 흐름을 끝까지 돌렸다.
시험용 계정 tester@my-universe.test(하늘 데모 우주), 새 일기는 가상 인물 '도윤'의 지어낸 짧은 글(사람 이름 1개). 이 문서에는 원문을 넣지 않는다.

```bash
# 1) 로컬 Supabase · Chroma 가 켜져 있어야 함(꺼져 있으면 scripts/dev_up.sh)
DAILY_ENTRY_LIMIT=60 uv run --frozen uvicorn main:app --port 8001   # 아래 '남은 문제' 1 때문에 하루 글 수 상한을 올려 띄움
# 2) 화면 빌드 + 실제 모드 e2e(포트 3000 = 백엔드 CORS 기본값). 기기마다 유료 일기 1편(약 $0.10)
cd infra/frontend && npx playwright test -c playwright.real.config.ts            # 휴대폰 · PC 둘 다
npx playwright test -c playwright.real.config.ts --project=mobile                 # 하나만
```

- 설정 `infra/frontend/playwright.real.config.ts`, 시험 `infra/frontend/e2e-real/real.spec.ts`. 가짜 모드 e2e(`playwright.config.ts`, `e2e/`)는 그대로다.
- 비밀번호는 루트 `.env.local` 의 `DEV_TEST_PASSWORD` 를 시험 코드가 읽기만 한다(출력 · 캡처 없음, 입력 칸은 가려짐).
- 시험이 끝나면 만든 기록(일기 · 위기 글)과 새로 생긴 사람을 지우고 말투 설정을 되돌린다. 되고 싶은 모습은 지우는 길이 없어 이력에 남는다(현재 판은 원래 문장으로 다시 저장해 둠).

## 남은 문제

1. (백엔드) 하루 글 수 상한이 기록의 `created_at` 으로 세져서, 오늘 시드한 데모 29편이 '오늘 쓴 글'로 잡힌다 → tester@ 는 시드 당일 새 글을 못 쓴다(429 daily_limit). 이번엔 `DAILY_ENTRY_LIMIT=60` 으로 띄워 피했다.
2. (백엔드) 데모 사람 민수 · 지은이 어느 행성과도 이어져 있지 않다(`/people` · `/universe` 의 planets 가 빈 배열). 데모 글에 이름이 나오는데 사람 고르기로 빛나는 행성이 없다.
3. (백엔드) 실제 결과에 `needs_confirm=true` 관계가 한 번도 나오지 않아(우주 선 35개 · 새 결과 관계 3개 모두 false) 점선 '맞아요/아니에요' 단추를 실제 모드로는 못 눌러 봤다(가짜 모드 e2e 에서는 통과).
4. (백엔드) 돌봄 `care.message` 안에 상담 전화 · 마들랜 안내가 문장으로 한 번 더 들어 있어, 아래 단추 · 안내와 겹쳐 길다.
5. (백엔드) 한 일기에서 '닿은 순간'이 2~3개 나와 결과 카드 위쪽이 길다. 생각 둘이 같은 인용 문장을 쓰는 경우도 있다(신념·원칙과 해석).
6. (화면, 작음) 되고 싶은 모습 4단계 입력 중 휴대폰에서 '다음' 단추가 아래 막대 뒤에 있을 수 있다(스크롤하면 보임).
7. 로그아웃은 Supabase 기본값(모든 기기에서 로그아웃)이다. 이 기기만 나갈지는 정할 일.
