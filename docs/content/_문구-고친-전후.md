# 화면 문구 고친 전후 (1판 → 2판)

1판(코드에서 그대로 옮김)에서 2판(다듬음)으로 바꾼 문구를 화면마다 모두 적었다. 화면 파일이 아니라서 읽는 규칙 블록을 붙이지 않는다. 고친 문구는 아직 코드에 옮기지 않았다(코드 연결은 prototype-build 몫). 서버(app/)가 보내는 문장도 화면에 보이므로 함께 다듬었고, 그런 줄은 이유 칸에 `서버`라고 적었다.

## 다듬은 기준

- 해요체로 맞춘다. 상태 표시(「~하는 중…」)와 버튼은 짧게 둔다.
- 버튼 이름은 누르면 일어날 일로 쓴다(「저장」보다 「고친 내용 저장」).
- 「결과 없음」과 「불러오지 못함」은 언제나 다른 문장으로 쓴다. 실패 문장에는 다음에 할 일(「잠시 뒤 화면을 새로 고쳐 주세요」)을 붙인다.
- 처음 쓰는 사람이 모르는 안쪽 말(JSON, MD, 기준 축, 관측 상태, 실수 표시, 결과 카드, 범례, 설정이 없어요)을 뺀다.
- 화면 첫 문장(`>`)은 제품의 가치 쪽으로 기울인다. 추천안 「지난 기록으로 나를 이해하기」를 따랐다(동규가 아직 정하지 않음, [확인 필요]).
- 우리 화면의 위치 말(위 칸, 아래, 맨 아래)을 뺀다. 디자인 개편으로 자리가 바뀌어도 맞게.
- 제품 고유 낱말(우주, 해, 작은 별, 행성, 별지기, 북극성, 블랙홀, 쌍행성, 금빛 고리, 실선 · 점선, 단정 · 고민 중 · 판단 보류, 말투 넷)은 그대로 쓴다.
- 코드에 없는 버튼 · 기능은 더하지 않는다. 보일 자리가 없는 상황 문구는 새로 쓰되 각 파일 메모에 「코드에 보일 자리가 없음」으로 적었다.
