- **지난 생각 고르기:** 고정 문턱 · 가산점 없음. 같은 세부 주제 먼저, 그 안은 중심 보정 유사도 순, 가장 크게 떨어지는 지점에서 자름, 주제 · 유사도 순위는 순위끼리 합침, 관련 높은 것을 앞에. 개수 상한은 운영 한도로만.
- **사람:** 실명 보관. 사용자별 사람 목록(이름 · 별명 · 관계) = 외부 AI로 보낼 때의 가명 표. 새 이름은 자동 등록, 헷갈릴 때만 묻기(동명이인 · 별명 · 이름인지 낱말인지). 확실하지 않으면 가명으로 보냄. 지우기 = 이름을 관계 말로 바꾸고 문장은 남김. 사람끼리 관계는 두지 않음.
- **되고 싶은 모습:** 사용자별 대상(한 말 · 가치 · 걸림돌 · "~면 ~하겠다" · 말한 날, 이력 보존). 며칠 쓴 뒤 허락을 구하고 대화하듯 4단계(요즘의 나 → 되고 싶은 나 → 걸리는 것 → 그때 해 볼 것). 거절은 "이번엔 넘어가기"(계기가 생기면 다시) / "그만 묻기"(사용자가 끔). 닿은 순간은 관측 Agent가 원문 근거로 찾고 별지기가 인정, 멀어진 순간은 표시 안 함, 거리 숫자 금지.
- **말 걸기 · 말투:** 다정하게 / 담백하게 / 고양이처럼 / 팩폭. 팩폭은 세게(반말 · 명령형 · 거친 표현 허용). 넘지 않는 선: 위기 신호면 돌봄 전환, 행동 · 핑계만 때리고 사람의 가치 · 외모 · 가족 · 정체성은 공격 안 함, 어쩔 수 없는 일(아픔 · 상실 · 남이 한 일)은 대상 아님, "오늘은 살살" 버튼. 모든 말투: 원문 근거, 지난 한마디 전체와 반복 검사, 사람 판정 금지. 기도(신에게 쓴 글) · 편지(특정 인물에게 쓴 글)에 맞게 받기.
- **마음 날씨:** 맑음(기쁨 · 신남) / 구름 조금(평온 · 잔잔) / 흐림(지침 · 울적) / 비(슬픔) / 천둥(화남 · 긴장) / 안개(막막함 · 혼란). 매일 묻지 않음: 언제든 고르는 선택지, 질문은 첫 만남과 기분이 안 드러난 글에만, 건너뛰면 다음엔 안 물음. 비 · 천둥이면 제안 없이 위로만(팩폭은 넘지 않는 선 기준).
- **운영(§8.0):** 사용자 맞춤 중심 + 작은 안전망(골든셋). 선호(말투 · 제안 빈도 · 시간대 · 영역 넘는 선 표시 정도)는 피드백으로 맞추고, 방향은 되고 싶은 모습이 정한다. 지표 = 만족(맞아요 비율 · 반응 · 계속 쓰는 비율) + 지향(가까워졌다는 느낌 · 여러 해에 대해 쓰는지).
- **위기 대응:** 자해 · 자살을 떠올리는 글이면 평소 틀을 멈추고 공감 + 안전 여부를 직접 묻기 + 자살예방 상담전화 109(24시간) · SNS 상담 마들랜 안내. 방법 · 장소 언급 금지.

Supabase Auth의 Google 연결). 구글 OAuth 클라이언트 만들기와 키 입력은 동규가 아침에 한다(Google Cloud 콘솔 → OAuth 클라이언트(웹) → 승인된 리디렉션 URI에 Supabase 콜백 주소 → 받은 클라이언트 ID · 비밀을 Supabase 로그인 설정에 입력). 5. **아침 보고에 영구 삭제 체크리스트를 넣는다:** Vercel 프로젝트 삭제, Supabase 프로젝트 삭제, Firebase 프로젝트 삭제, 카카오 앱 삭제, (선택) GitHub 저장소 보관(archive), 로컬 `.env*`(이제 쓸모없는 키)는 휴지통으로 — 각각 화면 경로와 순서. 백업은 만들지 않는다(동규: 코드만 남김). 남길 데이터가 있으면 동규가 삭제 전에 말한다.

## 5. 오케스트레이션 규칙

- 작업 묶음마다 에이전트 하나, `isolation: worktree`로 나눈다. 맡는 경로 밖 파일은 고치지 않는다. 공통 파일(`config.py` 등)은 오케스트레이터가 직접 합친다.
- 병렬 에이전트는 `git stash`를 쓰지 않는다(worktree끼리 stash를 공유함). 되돌림 확인은 `git diff > patch` → checkout → apply.
- 에이전트 프롬프트에는 이 문서의 해당 WS 줄과 §1 요약을 그대로 넣고, 수용 기준을 테스트로 확인한 뒤 끝내게 한다. 초록 실행이 "돌았다"는 뜻은 아니니 테스트 개수를 확인한다.
- **동규만 하는 것:** git push, 계정 가입, 키 입력, 앱 공개 범위 변경, Studio 파일 삭제. 에이전트는 멈추고 요청한다.
- 동규가 브라우저를 쓰는 동안 에이전트는 브라우저 도구를 쓰지 않는다(프롬프트에 명시).
- 동규 실제 일기는 Studio · 외부 AI로 보내지 않는다. 시험 데이터는 가상 인물과, 현호가 동의한 글뿐.
- Studio · Solar 호출은 실행마다 추정 비용을 기록하고 누적 $50을 넘기지 않는다.
- 결정이 필요한 갈래가 생기면 그 갈래만 멈추고 나머지는 계속한다. 대기 질문이 3개를 넘으면 멈추고 묶어서 묻는다.

## 7. 밤샘 진행 규칙 (동규가 자는 동안)

- 먼저 §2.5 bus-cignal 정리(목록 · 자동 연락 멈추기 · Supabase 일시 정지)를 하고, 동규 확인 없이 할 수 있는 일은 끝까지 한다: WS1 · WS3 · WS4 · WS7 → WS2(Studio) → WS5(로컬 Supabase) → WS6 → WS8 안전 사례 → WS10 초안. WS9는 배포 직전까지 준비만.

- 막히는 갈래(클라우드 생성 · 키 · 배포 · push · 결정)는 그 갈래만 멈추고, 할 수 있는 준비(스크립트 · 명령 · 체크리스트)를 끝내 둔다.
- 커밋은 로컬에만. 작업 묶음마다 브랜치 → 검증 → master에 합친다. push는 아침에 동규.
